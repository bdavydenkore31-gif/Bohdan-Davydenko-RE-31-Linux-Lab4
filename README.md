# Практична робота № 4

## Розгортання веб-сервісу для перегляду радіоспектра та 2D-аналізу SDR-сигналу засобами TensorFlow

**Середовище:** Raspberry Pi OS (Linux) · **Мова програмування:** Python 3 · **Вебфреймворк:** FastAPI · **Обробка:** NumPy і TensorFlow · **Джерело даних:** запис RTL-SDR Blog V4

У роботі розроблено вебзастосунок для відтворення збережених I/Q-даних SDR-приймача. Сервер обчислює спектр сигналу за допомогою FFT, передає дані через HTTP API та відображає спектр і водоспад у браузері. Реалізовано паузу, перемотування, зміну швидкості, розміру FFT і колірної шкали. Додатково створено панель 2D-аналізу: TensorFlow обробляє карту «час - частота», виділяє області перевищення фону та формує таблицю їхніх параметрів.

**TensorFlow використовується для фіксованої 2D-фільтрації та порогового аналізу. Навчена нейромережа, класифікатор модуляцій і ваги моделі в проєкті відсутні.**

У цій реалізації використовується готовий WAV-запис. Підключення до фізичного SDR-приймача та зміна його робочої частоти не виконуються. Відмінності від повного завдання наведено в розділі 10.

## 4. Формат вхідних даних

Файл `baseband_103600000Hz_19-36-09_27-10-2026.wav` містить два канали:

- **I** - дійсна складова сигналу;
- **Q** - квадратурна складова сигналу.

Відліки записано послідовно як `I, Q, I, Q, ...`. Кожен відлік каналу займає один байт і має значення від 0 до 255. Нульовому рівню відповідає 127,5.

Після нормування формується комплексний сигнал:

```text
I_norm = (I - 127.5) / 127.5
Q_norm = (Q - 127.5) / 127.5
z = I_norm + j * Q_norm
```

JSON поруч із WAV містить центральну частоту, частоту дискретизації, розрядність, назву пристрою та час початку запису. Центральна частота потрібна для підпису абсолютних частот на графіку.

`audio_103600000Hz_19-36-09_27-10-2026.wav` містить уже демодульоване моноаудіо. Для водоспаду радіочастотного сигналу використано саме **baseband WAV**.

## 5. Підготовка Linux і встановлення залежностей

Перевірте архітектуру, розрядність і версію Python:

```bash
uname -m
getconf LONG_BIT
python3 --version
```

Для цієї інструкції очікуються **aarch64**, **64** та **Python 3.10-3.13**. TensorFlow працює на CPU; CUDA не потрібна. Доступність готового пакета залежить від ОС та Python. TensorFlow публікує CPU-збірки для Linux ARM64; офіційна підтримка Linux насамперед стосується Ubuntu, тому роботу на конкретній Raspberry Pi OS потрібно перевіряти окремо. [Офіційна інструкція TensorFlow](https://www.tensorflow.org/install/pip).

Встановіть системні пакети:

```bash
sudo apt update
sudo apt install -y python3 python3-venv python3-pip unzip curl
```

Перенесіть `sdr-waterfall-tensorflow.zip` на Raspberry Pi. Розпакуйте його в окремий каталог, щоб не змішати з попередньою версією:

```bash
unzip sdr-waterfall-tensorflow.zip -d ~/sdr-tf
cd ~/sdr-tf/sdr-waterfall
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
```

Для тимчасових файлів інсталяції використайте каталог у домашній папці:

```bash
mkdir -p "$HOME/tmp-pip"

TMPDIR="$HOME/tmp-pip" python -m pip install \
  --no-cache-dir \
  --only-binary=:all: \
  -r requirements-tensorflow.txt
```

`TMPDIR` задає місце для тимчасових файлів цього запуску. `--no-cache-dir` вимикає кешування завантажень, а `--only-binary=:all:` обирає готові пакети замість збирання з вихідних кодів. Архів проєкту не містить встановленого TensorFlow: його завантажує pip.

Файл `requirements-tensorflow.txt`:

```text
-r requirements.txt
tensorflow>=2.20,<2.22
```

У `requirements.txt` залишаються FastAPI, Uvicorn та NumPy.

Перевірка імпорту й виконання 2D-операції:

```bash
python -c "import tensorflow as tf; print('TensorFlow:', tf.__version__); print(tf.nn.conv2d(tf.ones([1,3,3,1]), tf.ones([1,1,1,1]), strides=1, padding='VALID').shape)"
```

У разі успіху виводиться версія TensorFlow та форма `(1, 3, 3, 1)`. Цю перевірку слід виконати на власній Raspberry Pi; фактичний успішний результат на Pi поки не надано.

![Помилка нестачі місця під час інсталяції](screenshots/04-install-space-error.png)

*Рисунок 4 - Надана помилка `[Errno 28] No space left on device` під час завантаження пакета TensorFlow. Цей знімок показує незавершену інсталяцію, а не працездатний TensorFlow.*

Навіть за наявності вільного місця в домашній папці може бути заповнений інший розділ, наприклад `/tmp`. Для перевірки виконайте:

```bash
df -h /tmp "$HOME"
df -i /tmp "$HOME"
```

Перша команда показує місце файлових систем, друга - доступність inode. Якщо обмеження стосується тимчасового каталогу, повторіть встановлення з `TMPDIR="$HOME/tmp-pip"`, як наведено вище. За скриншотом без виводу цих команд точне місце заповнення не встановлено.

Якщо pip повідомляє `No matching distribution found`, перевірте розрядність ОС, Python і актуальність pip. Це інша помилка, не тотожна нестачі місця.

Префікс `(.venv)` означає активоване середовище Python для проєкту. Довідка: [тимчасові каталоги Python](https://docs.python.org/3/library/tempfile.html#tempfile.gettempdir), [кешування pip](https://pip.pypa.io/en/stable/topics/caching/).

## 7. Принцип роботи спектра, водоспаду та 2D-аналізу

Послідовність обробки:

```text
I/Q WAV -> комплексні відліки -> вікно Hann -> FFT
        -> усереднення потужності -> fftshift -> dBFS
        -> FastAPI / HTTP -> JavaScript / Canvas -> спектр і водоспад
```

Для кожного рядка беруться чотири короткі вікна, розподілені в межах відповідного інтервалу запису. Усереднюється потужність спектрів, після чого рівень переводиться в децибели.

**Спектр** показує рівень сигналу залежно від частоти для поточного моменту. **Водоспад** накопичує послідовні спектри: по горизонталі розташована частота, по вертикалі - час, а колір позначає рівень. Нові рядки додаються зверху; час підписано відносно початку запису.

Крок частоти визначається формулою:

```text
delta_f = sample_rate / FFT_size
```

Для `sample_rate = 2 048 000` і `FFT_size = 2048`:

```text
delta_f = 1000 Гц
```

За замовчуванням використано 40 рядків/с, тому один рядок відповідає 25 мс запису. Збільшення FFT покращує деталізацію за частотою, але підвищує обсяг обчислень.

| Елемент інтерфейсу | Призначення |
|---|---|
| Старт / пауза | Запуск або призупинення відтворення |
| У початок | Перехід до початку запису |
| Повзунок часу | Перемотування запису |
| FFT 512-8192 | Зміна частотної деталізації |
| Рядків/с | Кількість спектрів на секунду запису |
| Швидкість | Відтворення 0,5x, 1x або 2x |
| Повтор | Повторне відтворення після завершення |
| Прибрати DC | Віднімання середнього I/Q кожного FFT-вікна |
| Нижній / верхній рівень | Налаштування колірної шкали |

Рівні наведено в **dBFS на FFT-бін**, а не в dBm. Це цифрова шкала без калібрування потужності на вході приймача. Вибір чотирьох вікон на інтервал не гарантує виявлення дуже короткого імпульсу між ними.

### Двовимірна обробка TensorFlow

Для окремого аналізу використано фіксовані FFT **2048**, **20 рядків/с** та підсумкові **512 стовпців**. Ці параметри незалежні від налаштувань FFT звичайного водоспаду.

```text
Матриця спектрів [час x частота]
  -> перехід від dBFS до лінійної потужності
  -> TensorFlow avg_pool2d: усереднення кожних 4 частотних бінів
  -> повернення до dBFS
  -> медіанна оцінка фону кожного рядка
  -> віднімання фону
  -> TensorFlow conv2d: фіксований фільтр 3 x 5
  -> поріг перевищення фону
  -> пошук зв'язних областей у Python
  -> фільтр мінімальної площі
  -> карта, рамки та таблиця
```

Перед обробкою TensorFlow формує тензор `[1, rows, 2048, 1]`: один фрагмент, часові рядки, частотні біни й один канал. Після усереднення ширина становить 512 комірок. Крок карти для цього запису:

```text
Крок частоти = 2 048 000 / 512 = 4 000 Гц
Крок часу = 1 / 20 = 0,05 с
10 секунд запису = 200 рядків
```

Фільтр `conv2d` має фіксовані коефіцієнти та згладжує значення одночасно по часу і частоті. Коефіцієнти не навчаються. Після порога сусідні по стороні комірки об'єднуються у зв'язні області; діагональний дотик сам по собі не об'єднує їх.

**Це 2D-обробка засобами TensorFlow, а не навчена CNN.** Програма не визначає FM/AM, тип цифрової модуляції або конкретний передавач. Виклик `conv2d` сам по собі не означає наявності навченої нейромережі. [Опис операції conv2d](https://www.tensorflow.org/api_docs/python/tf/nn/conv2d).

| Прибрати DC | Окреме налаштування саме для аналізу |
| Затемнити фон | Виділення маски та рамок поверх карти |

У карті аналізу час зростає **зверху вниз**, на відміну від прокручуваного водоспаду з новими рядками зверху. Колір показує згладжене перевищення фону, обмежене для відображення діапазоном 0-30 дБ. У таблиці пікове перевищення може бути більшим за 30 дБ.

«Виділено, %» - частка комірок, що залишились після порога й фільтра площі. Це **не ймовірність правильного розпізнавання**. Таблиця та рамки показують до 64 найбільших областей; загальний лічильник може бути більшим.

TensorFlow завантажується при першому аналізі. Аналіз запускається кнопкою, а не на кожному кадрі водоспаду. Без встановленого TensorFlow звичайний водоспад працює, але API аналізу повертає пояснення помилки.

## 8. Перевірка HTTP API та обробки сигналу

Отримання метаданих:

```bash
curl -s http://127.0.0.1:8000/api/info | python -m json.tool
```

У відповіді для наданого файла мають бути такі значення:

```json
{
  "sample_rate": 2048000,
  "center_frequency_hz": 103600000.0,
  "samples": 20480000,
  "duration_seconds": 10.0,
  "frequency_min_hz": 102576000.0,
  "frequency_max_hz": 104624000.0
}
```

Наведено лише частину полів відповіді.

Перевірка блока спектральних даних:

```bash
curl -s -D - -o /dev/null 'http://127.0.0.1:8000/api/waterfall?fft_size=2048&rows_per_second=40&start=0&count=128'
```

Для першого повного блока цього запису очікуються статус `200 OK` і заголовки:

```text
x-rows: 128
x-bins: 2048
x-total-rows: 400
content-length: 262144
```

Тіло відповіді є двійковим масивом `uint8`: 128 рядків по 2048 частотних значень. Перерахунок байта в рівень:

```text
dBFS = -120 + value * 120 / 255
```

Основні маршрути:

| Метод і маршрут | Призначення |
|---|---|
| `GET /` | Сторінка вебінтерфейсу |
| `GET /api/info` | Параметри запису |
| `GET /api/waterfall` | Блок спектральних даних |
| `GET /api/analysis/status` | Наявність і стан завантаження TensorFlow |
| `GET /api/analysis` | Карта, метрики й області 2D-аналізу |
| `GET /docs` | Інтерактивна документація FastAPI |

Перевірка стану TensorFlow:

```bash
curl -s http://127.0.0.1:8000/api/analysis/status | python -m json.tool
```

`installed: true` означає, що Python знаходить пакет; `loaded: true` - що застосунок уже імпортував його. Сам запит стану не завантажує TensorFlow й не гарантує, що всі його операції працюватимуть.

Збереження результату аналізу всієї наданої запису:

```bash
curl -s -o analysis_result.json \
  'http://127.0.0.1:8000/api/analysis?start=0&count=200&threshold_db=10&min_area=12&remove_dc=false'
```

У цьому API `start` задається **в рядках при 20 рядках/с**, а не в секундах. `count` обмежений 256 рядками. Час початку дорівнює `start / 20`.

Результат JSON містить:

| Поле | Значення |
|---|---|
| `engine`, `version` | TensorFlow і його фактична версія |
| `trained_model` | `false`: навчена модель не використовується |
| `rows`, `bins` | Розміри карти |
| `threshold_db`, `min_area` | Застосовані налаштування |
| `region_count` | Кількість областей після фільтра площі |
| `occupied_percent` | Частка виділених комірок |
| `noise_median_dbfs` | Медіанна оцінка фону |
| `regions` | До 64 найбільших областей із частотними й часовими межами |
| `score_u8_b64` | Base64-карта перевищення фону, байти у порядку рядків |
| `mask_u8_b64` | Base64-маска областей: 0 або 255 |

Для карти перевищення: `значення_дБ = byte * 30 / 255`. Матриці мають форму `rows x 512`, ранні моменти розташовані першими. HTTP 422 означає неправильні параметри, HTTP 503 - відсутність або помилку імпорту TensorFlow.

Автоматичні перевірки:

```bash
python -m pip install -r requirements-test.txt
python -m unittest discover -s tests -v
```

Під час перевірки в середовищі розробки з **TensorFlow 2.21.0 пройшли 12 тестів**. Окрім FFT, WAV і HTTP, перевірено локалізацію штучного часо-частотного сплеску, пригнічення рівномірного фону, фільтр площі, розміри карт, межі областей і поведінку за відсутності TensorFlow.

Без установленого TensorFlow частина тестів 2D-аналізу пропускається. Щоб перевірити всю версію, спочатку встановіть `requirements-tensorflow.txt`. Успішний запуск усіх тестів на Raspberry Pi потрібно підтвердити окремим логом.

## 9. Локальна адреса та доступ до сервера

Адреса `127.0.0.1` є IPv4-адресою зворотного зв'язку. Вона звертається до **того самого пристрою**, на якому відкрито браузер. Назва `localhost` зазвичай відповідає адресам локального зворотного зв'язку.

Для адреси `http://127.0.0.1:8000`:

| Частина | Значення |
|---|---|
| `http://` | Протокол обміну браузера із сервером |
| `127.0.0.1` | Поточний пристрій |
| `8000` | TCP-порт застосунку |

Якщо відкрити `127.0.0.1` на телефоні, браузер звертатиметься до телефона, а не до Raspberry Pi.

### Перевірка мережі Linux

Для фіксації мережевих параметрів виконайте:

```bash
ip a
ip neigh
ip route
```

IP-адресу інтерфейсу видно у виводі `ip a`, сусідів локальної мережі - у `ip neigh`, а типовий шлюз - у рядку `default via` команди `ip route`. Таблиця сусідів заповнюється під час мережевого обміну й може бути порожньою.

Збереження результатів для звіту:

```bash
{
    echo '=== ip a ==='
    ip a
    echo '=== ip neigh ==='
    ip neigh
    echo '=== ip route ==='
    ip route
} > network_info.txt
```

Файл `network_info.txt` потрібно отримати на власній Raspberry Pi; фактичні IP-адреса та шлюз у цьому README не підставлялися.

### Перегляд із комп'ютера через SSH-тунель

Якщо сервер працює на localhost Raspberry Pi, на іншому комп'ютері виконайте:

```bash
ssh -L 8000:127.0.0.1:8000 pi@IP_RASPBERRY_PI
```

Замініть `IP_RASPBERRY_PI` реальною адресою Raspberry Pi, а користувача `pi` - власним, якщо він інший. Залиште SSH-сеанс відкритим і відкрийте `http://127.0.0.1:8000` на комп'ютері. Тунель передасть запити на сервер Raspberry Pi.

### Додатковий режим доступу з локальної мережі

Параметри запуску також дозволяють слухати всі IPv4-інтерфейси:

```bash
python run.py --host 0.0.0.0 --port 8000
```

Після цього в браузері іншого пристрою тієї самої мережі використовується `http://IP_RASPBERRY_PI:8000`. Адреса `0.0.0.0` задає прив'язку сервера і не є адресою, яку слід вводити в браузері. Доступ у цьому режимі залежить від мережевого з'єднання та правил міжмережевого екрана; окрему перевірку такого підключення потрібно задокументувати.

## 10. Системна інтеграція та відповідність завданню

### Приклад автозапуску через systemd

Наведено **приклад конфігурації для налаштування**, а не результат виконаної перевірки служби. Він розрахований на користувача `pi`, каталог `/home/pi/sdr-tf/sdr-waterfall` і встановлені залежності у `.venv`.

Створіть файл:

```bash
sudo nano /etc/systemd/system/sdr_web.service
```

Вміст:

```ini
[Unit]
Description=SDR Waterfall and TensorFlow Analysis
After=network.target

[Service]
Type=simple
User=pi
WorkingDirectory=/home/pi/sdr-tf/sdr-waterfall
ExecStart=/home/pi/sdr-tf/sdr-waterfall/.venv/bin/python /home/pi/sdr-tf/sdr-waterfall/run.py
Restart=on-failure
RestartSec=3

[Install]
WantedBy=multi-user.target
```

Якщо ім'я користувача або каталог інші, змініть їх у конфігурації. Перед запуском служби зупиніть ручний сервер через Ctrl+C, щоб звільнити порт 8000.

Команди встановлення і перевірки:

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now sdr_web.service
systemctl status sdr_web.service --no-pager
journalctl -u sdr_web.service -n 30 --no-pager
```

Перевірку автозапуску після перезавантаження потрібно виконати окремо та підтвердити власним скриншотом або логом. Наведена конфігурація зберігає адресу `127.0.0.1:8000`.

### Межі реалізованої версії

Початкове завдання передбачає віддалене керування SDR і передавання спектра через WebSocket. Фактично реалізована версія з 2D-аналізом має такі можливості:

| Пункт | Стан |
|---|---|
| FastAPI-сервер у Linux | Реалізовано; надано скриншот успішного запуску |
| HTTP GET для вебінтерфейсу | Реалізовано |
| Графік спектра та водоспад у Canvas | Реалізовано |
| Обробка справжнього I/Q-запису | Реалізовано через NumPy FFT |
| Пауза, перемотування, FFT і колірна шкала | Реалізовано |
| TensorFlow: 2D-фільтр і виділення областей | Реалізовано й перевірено в середовищі розробки |
| Виконання TensorFlow на Raspberry Pi | Потрібне окреме підтвердження після успішної інсталяції |
| Навчання моделі та розпізнавання модуляцій | Не реалізовано |
| HTTP POST `/api/frequency` | Не реалізовано |
| WebSocket `/ws/spectrum` | Не реалізовано; використовується HTTP GET |
| Живий потік із SDR і налаштування приймача | Не реалізовано |
| Служба systemd | Наведено приклад; фактична перевірка не підтверджена |
| Логи `ip a` та `ip neigh` на Raspberry Pi | Наведено команди для отримання; лог не надано |

TensorFlow є додатковою обробкою запису й не замінює WebSocket, живий захват або керування приймачем. Повне виконання всіх пунктів початкового завдання цією версією не заявляється.

Обмеження 2D-методу: межі залежать від порога і згладжування, короткі події можуть розмиватися, а за щільного заповнення смуги медіанна оцінка фону може зростати. Оцінка зайнятості та ширини області не є каліброваним вимірюванням параметрів передавача.

## 11. Результати та висновок

Під час роботи над версією з TensorFlow:

- Розроблено вебсервер на FastAPI із запуском через Uvicorn.
- Підготовлено середовище залежностей Python.
- Реалізовано читання PCM WAV із двома каналами I/Q і перевірку метаданих JSON.
- Побудовано спектр і водоспад для запису з центральною частотою 103,600 МГц.
- Додано керування відтворенням і параметрами відображення.
- Додано TensorFlow для усереднення частотних комірок, фіксованої 2D-згортки й порогового виділення.
- Реалізовано пошук зв'язних областей, фільтр площі та таблицю їхніх параметрів.
- Створено окремі HTTP-маршрути стану й результатів аналізу.
- У середовищі розробки з TensorFlow 2.21.0 пройшли 12 тестів.
- Для заданих параметрів аналізу наданого запису отримано 22 області й 17,51 % виділених комірок.
- Отримано скриншот успішного запуску сервера з адресою `127.0.0.1:8000`.

**Висновок.** Розроблено локальний вебсервіс для перегляду та двовимірної обробки записаних I/Q-даних. Поєднано FastAPI, Uvicorn, NumPy, TensorFlow і Canvas. Продемонстровано перетворення baseband-запису в спектр, побудову водоспаду та виділення часо-частотних областей за заданим порогом. Використано фіксовані операції TensorFlow без навчання нейромережі. Для завершення повного початкового завдання потрібні WebSocket, керування частотою SDR, підтвердження мережевого доступу й автозапуску; виконання TensorFlow на Raspberry Pi необхідно перевірити після успішної інсталяції.
